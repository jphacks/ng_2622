# JPHACKS 2026 Award Day でもらった声

> 記録（2026-11-15、EXPO で聞いた話を、聞いた本人が書き起こした）。ScenEnglish はファイナリストとして Award Day に出て、もらえたのは Innovator 認定だけだった。
> 声は EXPO で、審査員・スポンサー・一般の来場者から受けた。誰の言葉かは分けていない。
> 残すための記録で、全部を反映する必要はない。対応の方針や優先順位は、ここでは決めない。元は音声入力のメモで、言い回しは整えた。
> 「関係する文書」は、その話題が今どう決まっているかをたどるためのリンクで、今の実装への評価ではない。

## 言われたこと

### 評価された点

- 3D で場面を出すことに可能性がある、と多くの人に言われた。
- 発表とデモは好評だった。どんな人に向けたプロダクトかがよく伝わった、と言われた。

### 遊び方・ゲーム性

- 実況: 「ラジオ英会話」をやるとよいかも、と言われた。サッカーの実況のように、場面で起きていることを英語で実況できるのがよいらしい。そのためには、3D が止まっているより動いている方がよい。面白さだけでなく、役に立つかも大事。
  - 「ラジオ英会話」が何を指すかは確かめていない。場面の実況のことと受け取った。
- 力の差: 1 人だけ強い人がいると、その人が勝ち続けるので面白くない。その人にとっての相対的な難しさ（レーティング）や、ハンデがあるとよい。
  - 家族で Duolingo をしている人の話では、家族で競うなら、同じレベルで比べるのでなく、「このレベルをこれだけの時間やったら何ポイント」のような 1 つの指標にするとよい。そうすれば、英語の力が親より低い子どもでも、長く遊べばポイントで勝てるかもしれない。力の差があっても、適切な指標を出せるとよい。
- 何を言えばよいか: 今は、誰が何を言えばよいか分からない。3D の上に矢印などを出し、「この人の動作を言って」「この物について話して」と指せるとよい。
- みんなで話を作る: 4 人などで英文（日本語でもよい）を順に言い、言った文のとおりの話を 3DCG で再現する。誰かが変なことを言えば、3D も変になる。

関係する文書: 場面の作り方は [`scene-generation.md`](../design/scene-generation.md)、言わせたい文から場面を組み立てる形は [`scene-protocol.md`](../design/scene-protocol.md)、順位の出し方は [`screen-flow.md`](../design/screen-flow.md)。

### 学習（間違いの見せ方）

- 自分の間違った英文を図にして、「この表現だとこうなるからダメ」と分かるようにしてほしい。

関係する文書: [`weak-point-analysis.md`](../design/weak-point-analysis.md)（苦手の分析）。

### ターゲット

- そもそも英文で話すこと自体が難しい。英語が嫌いな人でも遊べるようにしてほしい。
- 幼稚園児や小学生が英才教育として楽しく英語を学べるなら、親としてお金を出しやすい。
- 英検 3 級・準 2 級・2 級の分け方はよいが、誰に向けたものかをもっと具体的にした方がよい。マーケティングとして、今は対象を広く取りすぎている。
  - 発表では誰に向けたかが伝わった、という声もあった（上の「評価された点」）。

関係する文書: 届けたい人は [`README.md`](../../README.md) の「今後の展望」の「3. 誰に届けるか」（小中高生）、採点の対象と級の分け方は [ADR](../adr/20261110-align-scoring-with-eiken-speaking-viewpoints.md)（英検の二次試験を控えた中高生）。

### 採点

いちばん大事な点として、何度も挙がった。

- 裏側の採点のロジックを見えるようにしてほしい。定量的で、納得できる説明がほしい。
- 採点のモデル: Claude でなくても、もっと安いモデルで採点のロジックは組めるはず。どのモデルにするかも考えた方がよい。
- 声の前処理: 前処理の段階で、話した言葉を正確に拾う方法を考えた方がよい（例: 文字起こしのモデルをファインチューンする）。
- 端末による差: 前処理で端末による差を無くし、公平にできるかを大事にした方がよい。最新の iPhone と、iPhone X のような古い機種とでは、文字起こしの性能が違うかもしれない。

関係する文書: 内容の採点は [ADR](../adr/20261110-score-content-with-checklist-f1.md) と [ADR](../adr/20261111-score-only-with-checklist-and-drop-handmade-scenes.md)、話し方の採点は [`azure-pronunciation-assessment.md`](../design/azure-pronunciation-assessment.md) と [`speech-scoring-research.md`](../design/speech-scoring-research.md)、端末での文字起こし（SpeechAnalyzer）と採点のモデルは [`usecase.md`](../design/usecase.md) の「Open Questions（決定木の状態）」の中の「文字起こし」「内容・表現の採点と講評」の項。本番で採点に使うモデルは [`backend/wrangler.jsonc`](../../backend/wrangler.jsonc) の `CLAUDE_MODEL`（2026-11-15 の時点では Sonnet 5.5）。安いモデルの試しは [PR #144](https://github.com/jphacks/ng_2622/pull/144)（苦手の場面の生成）。

## Hack Day の講評

Award Day の前の Hack Day で、審査員 3 人から受けた講評。名前は書かない。

- 面白い。周りに使ってもらい、英語の力がどれだけ伸びるか、2 週間続くかを確かめ、出た課題を解決してほしい。発表は「どんな人に届けたいか、その人の課題は何か、本当に解決できているか」から逆算する。
- 完成度が高い。「対戦の妥当性に納得感をもてる説明や、」（講評はここで切れていた）
- 話した結果が大幅に誤っている時、その風景を 3D で再現すると面白いかも。前置詞はとっさに出にくいので、ビジュアルで理解できそう。

Award Day の声と重なる所:

| Hack Day の講評 | Award Day の声 |
| --- | --- |
| どんな人に届けたいかから逆算する | ターゲット（誰に向けたものかを具体的に） |
| 英語の力がどれだけ伸びるか、続くかを確かめる | 競合と効果の確かめ（伸びるかを確かめる） |
| 対戦の妥当性に納得感をもてる説明 | 採点（ロジックを見えるように、納得できる説明） |
| 誤った結果を 3D で再現する | 学習（間違いを図にする）、遊び方（言った文のとおりの話を 3D で再現） |

## 受けて考えたこと

聞いた本人の所感で、言われたことでも、チームで決めたことでもない。

- 家族プラン: 家族向けのプラン（家族で遊ぶ形）を作ってもよいかもしれない。対象を小さい子がいる家族にして、「小さい子でも楽しく英語を学べる」という方向へ舵を切るのもあり。家族で Duolingo をしている人の話を受けて。
- 採点のベンチマーク: 今の採点のロジックは外から見えにくい。英語の答えに講師が付けた点が入った公開のデータベースがあるので、それをベンチマークにして、採点の裏側を鍛えるとよい。
