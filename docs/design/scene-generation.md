# 3D シーンの用意と自動生成

> Status: **合意済み**（2026-10-21、2026-10-24・2026-10-25 に改訂）。MVP の作り方と、将来の自動生成の構成を決めた。2026-10-24 に、部品を先に作り置いて AI が配置だけを書く形に改め、その範囲を Hack Day で作ることにした（下の「部品と配置のプロトコル」）。2026-10-25 に、AI の場面も遊ぶ前に作り置き、待合では難易度だけを選ぶ形に改めた。

## MVP（2026-10-21 に決定）

- Blender の Python スクリプトで、デモ用のシーンを複数作り、アプリに同梱する。費用がかからず、作り直しも簡単なため。
- 人や動物の出来が足りなければ、そこだけ権利のはっきりした無料素材（CC0）に差し替える。
- 試作: 公園のシーンを Blender 4.5 のスクリプトで組み立て、PNG・USDZ（110 KB）・GLB（263 KB）に書き出せた（画面なしで約 17 秒）。アプリの実機で開けるかは未確認。
- Hack Day の前に作ったシーンは「持ち込み」として使えるが、審査では評価されない（JPHACKS の規約）。

## 理想: シーンの自動生成

ホストが場面を文章で指定する（または「おまかせ」を押す）と、AI が新しいシーンを作る。

Cloudflare Workers で動かせないのは Blender であって、3D の生成そのものではない。構成の候補:

| 構成 | 仕組み | Workers のままでよいか | 長所 | 短所 |
| --- | --- | --- | --- | --- |
| A. 部品の組み合わせ | Claude が「どの部品を、どこに、何色で置くか」を JSON で書く（構造化出力）。iPhone の RealityKit が、同梱した部品からその JSON どおりに組み立てる | よい（Claude を呼ぶだけ） | 速い（数秒）、安い、見た目がそろう。同じ JSON を採点用のシーン定義にも使える | 部品に無いものは出せない |
| B. 3D 生成 API | Meshy などの 3D 生成 API に文章や画像を送り、できたモデル（GLB / USDZ）を iPhone が取りに行く | よい（HTTP で呼ぶだけ） | 部品に無いものも作れる | 生成に時間がかかり（推測で数十秒〜数分）、ラウンドの前に作っておく必要がある。1 回ごとに費用がかかる。利用条件の確認が要る |
| C. Blender をサーバーで動かす | Claude が Blender のスクリプトを書き、別のサーバー（コンテナ）で Blender を動かしてモデルを作る | 移行か追加が要る（Blender を動かせる場所） | 今の作り方をそのまま自動化できる | サーバーが 1 つ増える。生成の待ちが長い。AI が書いたスクリプトを実行するので、安全の対策が要る |

### 選んだ構成: C で部品を作り、A で並べる（2026-10-21 に決定）

将来の自動生成は、Blender を別のサーバーで動かす（C）。ただし Blender は部品作りに特化させ、配置は JSON で決める（A）。

- 部品: サーバーの Blender が、AI の書いたスクリプトで作る。まだ無い部品だけを作り足し、一度作った部品は保存して使い回す（保存先は Cloudflare R2 などを想定。推測）。
  - 2026-10-24 に改訂: よく使う動詞・名詞の部品は先に作り置く。要るときに作り足すのは、亀井さんのエージェント（スクラッチで作る）が試す。保存先は R2 に決めた。
- 配置: Claude が配置の JSON を書く。iPhone はその JSON どおりに部品を並べる。並べるだけなので数秒で済む。
- 理由:
  - A 単独の弱点（部品をたくさん用意しておく必要がある）を、C が部品を作り足すことで埋められる。生成を待つのは新しい部品が要るときだけになる。
  - 今の作り方（Blender のスクリプトで部品を作る）をそのまま自動化でき、技術としても面白い。
  - B は割高で品質も読めない。
- Hack Day の 14 時間では作らない。発表で「AI がシーンを自動で生成できるように展開すると、より有用なアプリになる」という今後の展開として示す。
- 作るときの注意（推測）: AI が書いた Python を Blender で実行するので、実行するサーバーはネットワークを切ったコンテナにし、CPU・メモリ・時間に上限を掛ける。生成には描き出しと書き出しで数十秒かかる（公園の試作で約 17 秒）ので、ラウンドの前に作っておく。

## シーンの形（2026-10-21 に決定）

MVP のシーンも、最初から「部品＋配置の JSON」の形で作る。将来の自動生成（C で部品を作り、A で並べる）にそのまま育てられ、採点用のシーン定義とも 1 つにまとまるため。

- 部品: ベンチ・木・犬などを 1 つずつ USDZ にする。Blender のスクリプトで作る。
  - デモ用の公園・教室・駅前は、シーンごとに 1 つの USDZ（[`assets/scenes/`](../../assets/scenes/README.md)）にまとめ、部品は名前付きの Xform に分けた（2026-10-24）。生成は `scripts/scene/<id>.py`。部品ごとのファイルに分けるのは、自動生成に進むときに行う。
  - 難易度「ふつう」のシーンとして、雨のバス停・海辺・カフェを足した（2026-10-24）。人と人のやりとりやハプニングがあり、描写してほしい要素は 10 個。難易度は `<id>.json` の `difficulty` に書く。
- 配置の JSON: シーンごとに、使う部品・位置・向き・大きさ・色と、採点用の情報（場面の説明、描写してほしい要素）を持つ。
  - デモ用のシーンは配置を USDZ に焼き込んだので、`assets/scenes/<id>.json` は難易度（`difficulty`）と採点用の情報（`description` と `elements`）だけを持つ。手で（または Claude で）書く。
- アプリ: RealityKit で部品を読み込み、JSON どおりに並べる。
  - デモ用のシーンは、USDZ をそのまま読み込んで表示する。

## 部品と配置のプロトコル（2026-10-24 に決定）

> 部品・配置の JSON・API の形は [`scene-protocol.md`](./scene-protocol.md)。

ねらい: 英語が苦手な人でも楽しく話せるよう、3D の場面を見せる。シーンを毎回 AI にスクラッチで作らせると、待ち時間が長く、何をしたいのかがぼやける。そこで、よく使う動詞・名詞の部品を先に作って保存しておき、AI は部品の組み合わせと座標だけを書く。速く安く場面を作れる。

上の「C で部品を作り、A で並べる」を、次のように具体化する。

- 部品は、要るときに作るのではなく、先に作り置く。日常でよく使う動詞・名詞を選び、プロトコルの形式（USDZ ＋メタデータ）で作り、保存する。今の 6 シーンの部品を使い回してもよい。
- スクラッチで作る役は、亀井さんのエージェントが試す。エージェントも同じプロトコルに従い、作った部品を保存し、配置を返す。
- 動き: v1 の基本は止まった場面とし、動作は人物のポーズの部品で表す。部品ごとに、簡単な動き（落ちる・まっすぐ動く・回る・揺れる）を任意で付けられる。
- 採点の情報: 配置を書く側（Claude・亀井さんのエージェント・人）が、同じ JSON に場面の説明（`description`）と描写してほしい要素（`elements`）も書く。要素の形は採点（`backend/src/scoring/scenes.json`）と同じにし、バックエンドはその JSON から採点する。2026-10-25 からは、採点は配置の情報と採点基準の段階で付け、要素は「主な見どころ」（参考）として使う（[`usecase.md`](./usecase.md) の採点）。
- 配り方: シーン（配置の JSON）はバックエンドに保存し、ID を付ける。部屋は今と同じく round で `sceneId` を配り、端末はその ID で配置の JSON と部品を取りに行く。
- 置き場所: 部品の USDZ は Cloudflare R2 に置き、端末は取ってきたものを持ち続ける。最初からある部品はアプリにも同梱し、電波が悪くてもデモが止まらないようにする。新しい部品は R2 に足すだけで使える。
- 作る入り口（2026-10-25 に改訂）: AI の場面は、遊ぶ前に手元のスクリプトでまとめて作り置き、人が目で確かめたものだけを Worker に同梱する。待合では、ホストは難易度だけを選び、場面はその部屋でまだ出ていないものからランダムに出る。2026-10-24 には「待合でホストが一言（例: リンゴが落ちる公園）を入れて作る」としていたが、書いた人だけが中身を知って有利になるのでやめた。詳しくは [`scene-protocol.md`](./scene-protocol.md) の「AI で場面を作り置く」。
- 配置の崩れ（重なり・宙に浮く・はみ出し）: v1 では直さない。バックエンドは保存するときに何も確かめない。崩れを見つけて自分で直すのは、配置を書くエージェントの役目とする。だめそうなら、① 部品の大きさから機械的に崩れを見つける、② 場面のスクリーンショットを AI に見せて直させる、の順に対処を広げる。プロトコルはそのための手がかり（部品の大きさ・接地点・正面の向き）をメタデータで渡す。アプリは、知らない部品を飛ばして残りを並べる。
- 保存の鍵: 部品とシーンを保存する API と、場面を作る口（`POST /scenes/generate`）は、Worker の secret に置いた合言葉で守る。アプリはどれも呼ばないので、アプリに合言葉は要らない。
- Hack Day で作る範囲: ① プロトコルの文書、② 部品、③ アプリが配置の JSON から部品を並べて表示する（まず今のシーンを 1 つプロトコルに直して確かめる）。④ 間に合えば、Claude が配置を書く口をバックエンドに足す。上の「自動生成は Hack Day では作らない」を、この範囲で改める。
