# 採点に使う音声 AI の調査

> Status: **調査メモ**（2026-10-21）。この調査をもとに、話し方と文字起こしは Azure の発音評価、内容・表現と講評は Claude に決めた（[`../adr/20261021-score-speech-with-azure-and-claude.md`](../adr/20261021-score-speech-with-azure-and-claude.md)）。
>
> サブエージェントが Web で調べた結果をまとめた。数値は各出典の条件（データセット、話者の母語、音読か自由発話か）でのもので、日本人学習者の自由発話での精度を示すものではない。

## 結論

1. **音声を LLM に渡して抑揚を採点させる方式は、今のところ当てにならない。**
   - ゼロショット（追加学習なし）で採点させると、人手評価との相関（PCC）は低い。韻律では GPT-4o 0.41（4 割は採点できず）、Qwen2-Audio 0.14。専用の Azure は 0.84。
   - 抑揚の情報はモデル内部に残っているが、答えに使われず、点数は 7〜9 点に偏る。微調整すれば 0.77 まで上がるが、ハッカソンの期間では現実的でない。
2. **抑揚・発音の点数は、Azure Pronunciation Assessment が既知の範囲で最も人手評価に近い。**
   - 正解文なし（自由発話）で、抑揚の点数（ProsodyScore）を返す。抑揚の評価は en-US のみ。
   - 費用は 20 秒 1 回あたり約 0.007 USD。iOS の公式 SDK がある。
3. **文字起こしの精度は、第三者の評価で ElevenLabs Scribe v2・MAI-Transcribe-2・Voxtral 3・Grok Voice Transcribe 2.0 が上位。**
   - 日本人学習者の英語での数値は、どこにもない。最終的にはチームで録音して比べる。
4. **音響の特徴（声の高さ・強さ・長さ・ポーズ）を数値にして LLM に渡す案は、効果が限られる。**
   - 感情認識では +1〜9 ポイント上がるが、強い LLM のゼロショットではほぼ変わらない。
   - 流暢さでは「話速・ポーズの集計値＋文字起こし」を渡すと、専用の式と同程度（順位相関 ρ≈0.77）。
   - L2 の抑揚の採点で、この方式を比べた研究は見つからなかった。
   - 声の高さ（F0）だけの指標は、日本人の英語の音読で r≈0.17〜0.22 と弱い。効くのは時間側の特徴（長さ・ポーズ・話速）と強さ。

### 構成の候補（所見。まだ決定ではない）

| 役割 | 担当 |
| --- | --- |
| ライブ字幕 | ストリーミングの文字起こし（第三者評価の上位から、自前の録音で選ぶ） |
| 発音・抑揚の点数 | Azure Pronunciation Assessment。または自前の特徴量と決まった式 |
| 描写の内容（場面に合っているか） | 文字起こしを LLM に渡して採点 |
| 講評の文章 | 点数・特徴量の数値とルーブリックを LLM に渡し、文章だけ書かせる |

LLM に自由に点数を付けさせると高い点に偏るので、点数は式か専用サービスで出し、LLM は説明の役に限るのが安全。

## 1. 音声を入力できる LLM

| 候補 | 音声入力 | 構造化出力 | 抑揚の判断の信頼性 | 音声入力の料金（/分） |
| --- | --- | --- | --- | --- |
| OpenAI gpt-audio-1.5 / gpt-realtime-2.1 | 可 | 記載なし（function calling は可） | 現行モデルの評価なし。旧 GPT-4o は韻律 PCC 0.41 | 約 $0.006〜0.019 |
| Google Gemini 3.x Flash / Flash-Lite | 可（1 秒を 32 トークン、16 kbps に落とす） | JSON スキーマに正式対応 | 現行モデルの評価なし。2.0 Flash は正確さ・流暢さ PCC 約 0.56 | 約 $0.0006〜0.003 |
| Anthropic Claude | **不可**（入力はテキストと画像） | — | — | — |
| Qwen Omni（API・オープン重み） | 可 | JSON Mode のみ | 旧 Qwen2-Audio は韻律 PCC 0.14 | 約 $0.00006〜0.005 |

なぜ当たらないか（研究からの説明）:

- 声の高さの情報は、音声エンコーダ（Whisper 系）の中間層までかなり残る。深い層で薄まり、LLM 側でさらに使われなくなる（arXiv 2510.20504、2601.11039）。
- 内部から読み取れるのに、答えでは使われない。話し方を内部表現から当てると 82〜85% だが、自由に答えさせると 19.7%（Qwen2-Audio、arXiv 2609.00727）。
- 文の内容と声の調子が食い違うと、内容に従う（DEAF、arXiv 2603.18048）。今回は採点の指示に場面の説明が入るので、この弱点に当たりやすい。
- 点数が較正されていない。人手で 6 点以下の発話 863 件に、6 点以下を 1 件も付けなかった（arXiv 2601.16230）。

## 2. 発音・抑揚評価の専用 API

| 候補 | 正解文なし | 抑揚の評価 | 精度の根拠 | 料金（20 秒 1 回） |
| --- | --- | --- | --- | --- |
| Azure Pronunciation Assessment | ○ | ○ ProsodyScore、単語ごとの区切り・平板の判定（en-US のみ） | 第三者: 日本人を含む音読で順位相関 0.74。ただし点数の水準は人とずれる | 約 $0.007 |
| SpeechSuper | ○ | △ リズム、文末の上がり下がり、強調 | 自社の主張のみ | 約 $0.03 |
| Speechace | ○ | × 自由発話では語の強勢のみ | 公開なし | 約 $0.025 |
| ELSA | ○（20 秒を超える発話が必要） | ○ intonation_score（短い発話では返らない） | 公開しないと明言 | 約 $0.04〜0.05 |
| Language Confidence | ○ | × | 数値なし | 約 $0.02 |

Azure の注意点:

- 無料枠（F0）は同時 1 セッションまでで、同時プレイには使えない。有料（S0）は既定で同時 100。
- 自由発話の評価は通常の文字起こしとは別のモデルを使う。Microsoft は、文字起こしを先に取り、それを正解文にして評価する方法も勧めている。
- 語彙・文法を評価する内容評価は廃止済み。内容の採点は LLM で補う。

- 日本人学習者の訛り・言い間違いでの数値は、どこも出していない。会場に近い雑音で 20 秒の発話を 20〜30 本録り、上位を比べるのが確実。

- Apple の SFSpeechRecognizer は話速・ポーズ・声の高さの特徴を返す。発音の採点はしない。

## 4. 音響特徴を LLM に渡す案

| 研究 | 課題 | 結果 |
| --- | --- | --- |
| SpeechCueLLM（arXiv 2407.21315） | 感情認識 | 微調整で 70.1 → 72.6。Claude 3.5 Sonnet のゼロショットは 59.0 → 59.2 でほぼ変わらず。特徴だけでは 27.6 |
| VowelPrompt（arXiv 2602.06270） | 感情認識 | GPT-4o のゼロショットで 53.6 → 60.7。母音ごとの F0・強さ・長さを言葉にして渡す |
| CCoT-Emo（arXiv 2509.25458） | 感情認識 | 音声 LLM に特徴も渡すと +7〜9。うち音響特徴の寄与は約 3 |
| 流暢さ（arXiv 2608.26137） | 日本語を含むアジアの学習者の自由対話 | 文字起こし＋ポーズの集計値で ρ=0.774。専用の式は 0.764 |

従来の特徴量による韻律の評価（日本人大学生の英語の音読、ERJ。arXiv 2607.13721）:

| 対象 | F0 だけ | F0＋強さ | 最良の手法 | 人間同士の一致 |
| --- | --- | --- | --- | --- |
| 文の抑揚 | 0.17 | 0.22 | 0.33 | 0.45 |
| リズム | — | — | 0.45 | 0.49 |
| 語のアクセント | 0.00 | — | 0.42 | 0.47 |

- 見本（母語話者や TTS）の F0 輪郭と比べる方式も、発話単位では弱い。正しい抑揚には幅があり、1 本の見本では表せない（Interspeech 2022、SLATE 2026）。
- 効くのは時間側の特徴: 音素の長さのずれ、ポーズ、話速。強さを足すと上がり、F0 を足すと下がった例もある。
- 韻律は人間同士でも一致が r≈0.45〜0.75 と低い。点数は 3〜5 段階の粗さで見せるのが妥当。

## 5. 特徴を取り出すツール

いずれも 20 秒の音声を CPU で 1 秒未満で処理できる（Apple M4 で実測。CREPE の大きいモデルを除く）。

| 環境 | ツール | ライセンス | 備考 |
| --- | --- | --- | --- |
| Python | Parselmouth（Praat） | GPL-3.0 | F0 11 ms、強さ 4.5 ms |
| Python | librosa | ISC | pyin 453 ms |
| Python | openSMILE | 非商用のみ | 88 特徴を 285 ms |
| TypeScript | pitchy | MIT | F0 113 ms |
| TypeScript | pitchfinder | GPL-3.0 | |
| iOS | SFVoiceAnalytics / SFSpeechRecognitionMetadata | OS 標準 | 声の高さ（対数で正規化した値）、話速、平均ポーズ長 |
| iOS | AudioKit（PitchTap） | MIT | リアルタイム向け |
| 時刻合わせ | STT の単語タイムスタンプ、torchaudio の forced_align、WhisperX | — | 約 1 秒 |

手元での試し（TTS の音声 3 本を Parselmouth で解析）では、「平板かどうか」と「文末が上がるか下がるか」は数値ではっきり分かれた。人の発話での精度は試していない。

## 次にやること

- 会場に近い雑音で、日本人の 20 秒の自由発話を 20〜30 本録る。文字起こしの上位候補の WER と、話し終わりから結果までの時間を測る。
- 同じ録音を Azure Pronunciation Assessment にかけ、抑揚の点数がチームの感覚と合うかを見る。
- 採点の構成（上の表）を決めたら、長く効く判断なので ADR に残す。
