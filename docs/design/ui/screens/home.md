## 課題

- 「部屋を作る」「部屋に入る」の 2 つから選ぶ形で、初めての人がどちらを押すか迷う。
- 名前と色の欄が毎回目に入るが、変えることはほとんど無い。

## 改善案

## 決定

（2026-11-12 に決定）

- 右上に設定の丸いボタン（歯車）を置く。
- 主ボタンは「あそぶ」の 1 つにする。押すと自分の部屋ができ、ホストとして待合に入る（前の「部屋を作る」と同じ動き。マイクの許可もここで聞く）。ほかの人の部屋に入るときも、まず「あそぶ」で自分の部屋に入り、待合の「他のルーム」から移る（[`lobby.md`](./lobby.md)）。「部屋に入る」のボタンは無くす。
- 名前と色の欄はホームから無くす。名前は最初の画面（[`first.md`](./first.md)）で決め、名前と色は設定で変える（[`settings.md`](./settings.md)）。
- 「あそぶ」の下に、きろくへの入口を置く（2026-11-12）。下の 2026-11-13 の直しで、枠だけのボタンに変えた。

（2026-11-13 のレビューで直した。案 B）

- 大きなジオラマ（画面の幅の 8 割ほど）、その下に「ScenEnglish」、下の方（親指の届く所）に「あそぶ」（紫の塗り）と「きろく」（枠だけ）を、同じ大きさ・同じ幅で縦に並べる。右上の設定の歯車は今のまま。
- 「きろく」は文字だけにする（「これまでの N 回」と時計のアイコンは外す）。記録が 0 件でも同じ形で出し、押すときろくの 0 件の画面が開く。
- ジオラマとタイトルのまとまりは、歯車の行と下のボタンのあいだの空きに、上 2 : 下 3 で置く（見た目の重心が少し上に来るように）。ジオラマとタイトルの間は狭くする。キーボードが出たときなどは、ジオラマが縮む。
- 待合の「他のルーム」で入れなかったときにホームに戻って出していた知らせ（「入れませんでした（満員）」）は無くした。入れないときは今の待合のまま、シートに理由を出す（[`join.md`](./join.md)）。

（2026-11-13 に決定。Award Day の TestFlight の版だけ）

- ビルド設定 `TITLE_DIORAMA` が `hackathon` のときだけ、ジオラマを企業の 3D 広告の見本（JPHACKS が提供した場合に見立てたハッカソンの会場。[`assets/title/`](../../../../assets/title/README.md)）にする。既定（空）は今の場面のままで、App Store の版も既定のまま出す。作り方は [`docs/app-store/README.md`](../../../app-store/README.md) の「Award Day の TestFlight 版の作り方」。
- 会場は 1 周させず、横断幕と看板の両方が見える向きを中心に、左右へ ±40 度を 20 秒で 1 往復する（端でなめらかに折り返す）。1 周させると、壁の裏が手前に来て中が見えない時間が長いため。今の場面は今のまま 1 周する。
- 「ScenEnglish」の下に、小さく灰色で「広告の見本：JPHACKS」と出す。実際の提供ではないので「提供」の語は使わない。
- 会場の USDZ が無い・読めないときは、今の場面に戻し、字も出さない（ホームを空にしない）。
