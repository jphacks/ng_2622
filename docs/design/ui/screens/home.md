## 課題

- 「部屋を作る」「部屋に入る」の 2 つから選ぶ形で、初めての人がどちらを押すか迷う。
- 名前と色の欄が毎回目に入るが、変えることはほとんど無い。

## 改善案

## 決定

（2026-11-12 に決定）

- 右上に設定の丸いボタン（歯車）を置く。
- 主ボタンは「あそぶ」の 1 つにする。押すと自分の部屋ができ、ホストとして待合に入る（前の「部屋を作る」と同じ動き。マイクの許可もここで聞く）。ほかの人の部屋に入るときも、まず「あそぶ」で自分の部屋に入り、待合の「他のルーム」から移る（[`lobby.md`](./lobby.md)）。「部屋に入る」のボタンは無くす。
- 名前と色の欄はホームから無くす。名前は最初の画面（[`first.md`](./first.md)）で決め、名前と色は設定で変える（[`settings.md`](./settings.md)）。
- 「あそぶ」の下に、きろくへの入口を置く（2026-11-12）。下の 2026-11-13 の直しで、枠だけのボタンに変えた。

（2026-11-13 のレビューで直した。案 B）

- 大きなジオラマ（画面の幅の 8 割ほど）、その下に「ScenEnglish」、下の方（親指の届く所）に「あそぶ」（紫の塗り）と「きろく」（枠だけ）を、同じ大きさ・同じ幅で縦に並べる。右上の設定の歯車は今のまま。
- 「きろく」は文字だけにする（「これまでの N 回」と時計のアイコンは外す）。記録が 0 件でも同じ形で出し、押すときろくの 0 件の画面が開く。
- ジオラマとタイトルのまとまりは、歯車の行と下のボタンのあいだの空きに、上 2 : 下 3 で置く（見た目の重心が少し上に来るように）。ジオラマとタイトルの間は狭くする（下の 2026-11-13 の実機の確認で、間に余白を置くように直した）。キーボードが出たときなどは、ジオラマが縮む。
- 待合の「他のルーム」で入れなかったときにホームに戻って出していた知らせ（「入れませんでした（満員）」）は無くした。入れないときは今の待合のまま、シートに理由を出す（[`join.md`](./join.md)）。

（2026-11-13 の実機の確認で直した）

- 場面が回って斜めになると、手前の角がジオラマの枠の下にはみ出し、枠の外が描かれないので水平に切れて見えていた（タイトルの白い地が被っているように見えた）。枠を高くし（270pt → 340pt）、そのぶんカメラを離して（距離 4.2 → 5.3）、場面の大きさ（画面の幅の 8 割ほど）は変えずに、どの向きでも角が枠に収まるようにした。枠が縮むとき（小さい画面・キーボードが出たとき）は、場面も同じ比で縮むので切れない。
- タイトル「ScenEnglish」は少し下げ、場面との間に余白を置く。広げた枠の下の余裕がそのまま余白になる（iPhone 17 で、場面のいちばん下からタイトルの文字の上端まで、斜めのとき 52pt ほど・正面に近いとき 93pt ほど。文字の枠（Text の上端）までは、斜めのとき 42pt ほど。2026-11-13 に、枠の下に「PR」の札の行（26pt）をいつも取る今の作りで測り直した。札の行は、この余白の中にある）。余裕は、ホームに出す場面（かんたんの例、今は gen-v2-eiken3-park-01）で測ったもの。例の場面を替えたら、回して切れないかを確かめ直す。最初の画面も同じ。
- 最初の画面で名前を打っている間（キーボードが出ている間）は、歯車の行（最初の画面では歯車は出さない）と下の余白を詰め、ジオラマをさらに縮めて、小さい画面（iPhone SE 3rd）でも「はじめる」がキーボードに隠れないようにする。詰めるかは、欄のフォーカスではなく、並べる所の下の安全域（キーボードが出ていると大きくなる）で決める。キーボードを避けて並べ直すのと同じ計算の中で決まるので、並びはキーボードと一緒に動き、欄を押した瞬間に跳ばない。タイトルと下のボタンの間は、小さい画面でも 28pt は空ける（名前を打っている間は 8pt）。名前を打っている間の下の余白は 16pt で、「はじめる」の影の下とキーボードの間に 10pt ほど空く。

（2026-11-13 に決定。広告の 3D。[ADR](../../../adr/20261113-decide-title-diorama-on-server-with-expiry.md)。入れ替えの時と札は同日に [ADR](../../../adr/20261113-swap-title-diorama-in-place-and-label-as-pr.md) で直した）

- ジオラマは、ふだんは今の場面（公園）。広告の 3D があるときだけ、それに替える。今は企業の 3D 広告の見本（JPHACKS が提供した場合に見立てたハッカソンの会場。[`assets/title/`](../../../../assets/title/README.md)）。
- 広告の 3D を出している間は、3D の下・タイトルの上に、枠線の小さな「PR」の札（紫の枠と紫の字、角の丸い四角）と広告主の名前（「JPHACKS」、灰色）を 1 行で中央にそろえて出す。公園のときは何も出さない。
  - 「PR」の札はアプリに固定で、サーバーからは変えられない（ステマ規制。広告と分かる表示を設定で消せないようにする）。名前はサーバーの `caption`。字だけが替わったときは、3D はそのままで札の字だけを替える。
  - 見落とされないよう、札は 12pt の太字、名前は 13pt の太字で、どちらも背景との明るさの比が 4.5:1 以上の色（札は accent、名前は muted）。VoiceOver では「PR、JPHACKS」と 1 つで読む。
  - 3D の枠（340pt）の下に札の行（26pt）をいつも取り、公園のときは空けておく。3D の描く所の高さは公園と広告で同じで、3D と札は重ならず、タイトルとボタンの位置も変わらない（iPhone SE・17・18 Pro Max と、最初の画面でキーボードが出たときで確かめた）。公園の距離は 5.3 → 4.9 にして、前と同じ見た目の大きさを保つ。
- 出すかは、Live（App Store と TestFlight の版）ではサーバーが決める。起動時と前に戻ったときに毎回 `GET /title` で確かめ、確かめが終わった時点で、ホームを見ている途中でもその場で入れ替える。
  - 新しい 3D は裏で取って先に読み込み（読めなければ入れ替えずに消す）、前の 3D の上に置く。描かれたと見なせたら（置いてから 0.6 秒たち、場面が動いていたら。RealityKit は描いた時を知らせないので時間で見なす）、前の 3D を薄くする・札の出し入れを、同じ 0.4 秒で同時に行う。
    - 広告の 3D は、描かれたと見なせるまでほとんど見えない濃さ（0.02）で置き、見なせたら札と同時に濃くする。広告の 3D が札より先に見えることは無い。
    - 公園は、上にすぐ出す（0.02 の濃さでは描かれず空になったため）。前の広告の 3D と札は、0.6 秒ほど公園の後ろに見えてから、同時に薄くなる。
    - 描かれたかの見なし方は目安なので、遅い端末では入れ替えの途中で 3D がごく短く薄く見えることはありうる。
  - 待ち（3D を出すのを遅らせる）は入れない。初めて入れた端末では、公園が一瞬出てから会場に替わる。
  - サーバーが出さなくなったとき（`title` が null）と、期限（`expiresAt`）を過ぎたとき（つながっていなくても）も、確かめが終わった時点で公園に戻る。見ている途中に期限が来ても、その場では替えない（次に前に戻したときに替わる）。
  - 最初の画面（名前を打つ所）の 3D も同じ。
  - きろく・設定を開いている間は 3D を外しておき、閉じたら出し直す。3D がもう読み込み済みなら、描かれた状態から始め、3D と札をすぐ一緒に出す（読み込み済みでなければ、札も一度消し、3D と一緒に出す）。
  - 既知（直していない）: 「公園 → 広告 → 公園」の入れ替えが 0.6 秒の間に続くと、向きの違う公園が一瞬 2 つ重なって見えることがある（まれ）。
  - JPHACKS は staging だけで出し、本番（App Store の利用者）には出さない。
- Mock では、ビルド設定 `TITLE_DIORAMA` が `hackathon` のときだけ、同梱の会場と札を出す（サーバーには聞かない）。
- 広告の 3D は 1 周させず、正面（横断幕）と手前右（看板）の両方が見える向きを中心に、左右へ ±40 度を 20 秒で 1 往復する（端でなめらかに折り返す）。1 周させると、壁の裏が手前に来て中が見えない時間が長いため。公園は今のまま 1 周する。
- 広告の 3D は、壁があって公園より背が高いので、カメラを公園（4.9）より離す（5.5）。振りの両端と中央で、角と壁の上が切れず、札とも重ならないのを確かめた（iPhone SE・17・18 Pro Max）。
- 3D が読めない・壊れているときは、公園に戻し、札も出さない（ホームを空にしない）。端末に取っておいたものなら消し、次に確かめたときに取り直す。
