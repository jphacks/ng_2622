## 課題

- 振り返り（文字起こし・内容の内訳・講評・見本の答え・自分の声）は、遊んだ直後にしか見られなかった。
- 同じ場面をもう一度遊んだときに、前と比べて何が言えるようになったかを見返せなかった。

## 改善案

- 野沢さんの PR #98 は、日付順の一覧と、合計点・語数の推移のグラフを出す形だった（記録はサーバーに置く）。
- 2026-11-12 に、仮の画面を比べて「横 = 場面、縦 = その場面の記録」の形に決めた。推移の集計は、苦手の画面（画面設計書 v2 の `weak.md`）で使う。
- 同じ日の初めの形は、最新の採点の要約（合計・3 つの棒・言えた項目）と「振り返りをひらく」、前の回のカードの一覧（「これまで」）で、押すと別の画面で振り返りを開き直していた。画面を見て、押して移る所を無くし、1 枚の縦の流れにした。
- 2026-11-13 のレビューで、見出し「りれき」と、3D の横の並び（隣が小さく薄くのぞく）、上に残る名前と回数の行を見直した。案 A〜C を比べ、「案 B 改」（3D と名前を白いカードに入れて横に並べ、下へスクロールすると小さな 3D と名前だけが上に残る）に決めた。
- 案 B 改を実装した画面を見て、カードと隣ののぞきはやめ、3D を画面の幅いっぱいにして横に送る形にした。止まった後の形（小さな 3D と名前だけ）はそのまま。ぼかしの壁は、名前のすぐ下まで上げた。

## 決定

（2026-11-12 に決め、2026-11-13 のレビューで今の形に直した。記録の置き場所は [ADR](../../../adr/20261112-keep-play-records-on-device-one-file-per-round.md)）

- 左上に戻るボタン、真ん中に見出し「きろく」。見出しはスクロールで流れて消え、戻るボタンは上に残る。
- 場面を横に並べる。1 つの場面（3D と、その下の場面の名前）を画面の幅いっぱいに出し、横に 1 つずつ送る。枠（カード）は付けず、隣の場面はのぞかせない。矢印・ページの点・「N 回あそんだ」は出さない。場面の並びは、最後に遊んだのが新しい順。
  - 3D はゆっくり回り続け、触って回せない。記録の中の配置から組む。
  - 3D を出すのは、選んでいる場面とその両隣（同時に 3 つまで）。それより離れた場面は印だけにする。
  - 3D の後ろには、小さな立方体の印を薄い灰色で置く。塗りの板は置かない。組み上がって描かれるまで数秒かかることがあり（シミュレータで 1〜4 秒、長いと十数秒）、その間も何も無い所を作らないため。描かれると、ジオラマの盤に隠れる。
  - どの場面を選ぶかは、横のスクロールが止まってから決める。速く送ったときに、通り過ぎる場面の 3D を作って捨てないため。
  - 読み上げ（VoiceOver）では横に送れないので、場面の操作「次の場面」「前の場面」で替える。遊んだ回数は、読み上げでだけ伝える。
  - 同じ場面かどうかは、場面の ID で見る。部屋がその場で作った場面は、毎回 ID が違うので、1 回ずつ別の場面になる。
- その下に、選んでいる場面を遊んだ回の振り返りを、新しい順に縦に並べる。画面は移らず、下へスクロールすると続く。押す所は無い。
  - 回ごとに、日付と時刻の区切り（「─── 11/13 3:02 ───」）を置く。「最新」は付けない。同じ日に何回か遊んでも見分けられるよう、時刻も出す（24 時間）。
  - 中身は遊んだ直後の振り返り（[`review.md`](./review.md)）と同じ部品で、同じ並び（難易度・合計 → 3 つの軸の棒 → あなたの描写（下線と凡例）→ 場面のチェック → 場面と合わない描写 → 次の一つ → 見本の答え → 言い直してみよう → 話し方の一言）。順位は出さない（記録には自分の結果しか無い）。
  - その回の録音が残っていれば、「あなたの描写」から聴ける。録音は、きろくを読み直すときに 1 度だけ読む。鳴らす口はきろくで 1 つを共有し、別の回を押したら前の回を止める（2 本同時に鳴らさない）。
  - 縦の流れの中には 3D を出さない（3D は横の並びの中だけ）。
  - 回の数が多い場面でも重くならないよう、回の振り返りの部分だけ遅延して作る（横の並びは遅延しない所に置いたまま）。
- 下へスクロールすると、3D は上端（戻るボタンの上端の高さ）に着くまで一緒に上がり、そこで止まる。止まってからは、3D を小さくし（半分ほど）、名前をそのすぐ下に寄せる。上に残るのは、小さな 3D と名前だけ。帯・線・回数・点は置かない。
  - 止まってから縮み切るまでのスクロールの量は、縮む量と同じにする。縮む間は、下の中身の上端が名前の下端に付いてくる（中身が名前の下に潜らない）。
  - 縮み切った後は、下から上がってくる中身が、名前の文字のすぐ下で、地の色のぼかしのグラデーション（疑似的な壁）に溶けて消える。振り返りを読める所を広くするため、3D と名前の下の空きは詰める。
  - 止まった 3D と名前の後ろと、その上（画面の上端まで）は地の色でふさぎ、流れていく見出しや中身を見せない。そこを押しても、見えていない中身には届かない（戻るボタンは、その上に重ねて押せる）。
  - 小さくするのは、同じ 3D の見た目の大きさだけ。3D は作り直さない。
  - 縮み切っている間は、横に送らない（上に戻ると送れる）。止まった 3D と名前の所を押しても、下に隠れた中身には届かない。
  - 縮んでいる途中か縮み切った所で場面を替えたら（縮み切る前に横に送ったか、読み上げの操作から）、縮み切った所（その場面の最新の回の頭が名前のすぐ下に来る所）までスクロールする。
- 下にスクロールして戻っても、横の並びは作り直さない（3D と横の位置がそのまま残る）。
- 一番下は、下に行くほど地の色に溶かして、続きがあることを示す。矢印や文言は置かない。
- 「苦手」への入口は、下に固定したフッターのボタン「苦手をぶっとばせ！」（文言は 2026-11-12 に確定）。アプリのほかのボタンと同じ紫の単色。下へスクロールして 3D が止まり始めたら下に隠れ、上に戻ると出る。
  - 記録が 5 件以上のときだけ出す。4 件以下は入口ごと出さない（2026-11-13。数えるのは内容の内訳のある記録で、苦手の分析が AI を呼べる数と同じ。苦手の分析の設計 `docs/design/weak-point-analysis.md` の 4 章）。
  - ボタンの後ろは、上ほど地の色に溶かした帯にし、下を流れる文字がボタンのすぐ上で消えるようにする。入口があるときは、振り返りの下をフッターの高さだけ空ける（一番下まで送ったときや、振り返りが短くてフッターが隠れないときも、最後の中身がフッターに隠れない）。
  - 押すと、苦手の画面がきろくの上に重なる。きろくは出したままにし（戻ると、選んでいた場面とスクロールの位置が残る）、重なっている間は、きろくの 3D を外す（下の「3D の入った画面の重ね方」）。
- 色・角丸・文字は、今のアプリ（Theme）にそろえる。
- 3D の入った画面の重ね方（2026-11-12、シミュレータで確かめた）:
  - 不透明な画面で覆われたまま残った 3D があると、ほかの 3D（新しく作ったものも）が描き直されなくなることがある。そこで、ホームの 3D はきろく・設定が重なっている間、重なる動きが終わってから外し、戻ったらすぐ出し直す。
  - 一瞬だけ出し入れするのとは違い、画面の切り替えと同じ時には外さない。
  - それでも、新しく作った 3D が数秒〜十数秒描かれないことが残っている（原因は未特定。実機では確かめていない）。
- 記録が 0 件のときは、「まだきろくがありません」「あそぶと、ここに場面と採点がたまります。」と出す。
- きろくの画面を閉じたら、記録の場面から組んで覚えた 3D を忘れる（遊ぶたびに増えるので、持ち続けない）。
- Mock では、例の記録を 12 件、初めから出す（`MOCK_SAMPLE_RECORDS`。端末には書かない）。Mock で遊んで保存した記録も一緒に出る。
