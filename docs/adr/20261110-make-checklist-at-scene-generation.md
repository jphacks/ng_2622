# 2026/11/10 チェックリストは場面を作るときに Claude が作り、コードが場面と照らして確かめる

## Status
- accepted

## Situation
- 内容の点を、場面ごとのチェックリストと正しさの F1 で付けると決めた（[20261110-score-content-with-checklist-f1](./20261110-score-content-with-checklist-f1.md)）。
- 場面は、生成のときに Claude が説明文・要素（`elements`）・部品と関係（`place`・`facing`・`motion`）を書き、プログラムが座標に直す。作り置きの JSON（`backend/src/scenes/pool/`）には計算後の座標（`position`）だけが残り、関係は残らない（[20261024-compose-scenes-from-stored-parts](./20261024-compose-scenes-from-stored-parts.md)）。
- 要素（`elements`）は、日本語の名前・満点の言い方（`accept`）・半分の言い方（`partial`）・配点を持つが、今の採点では使っていない（[20261025-score-content-with-layout-and-rubric-bands](./20261025-score-content-with-layout-and-rubric-bands.md)）。

## Context
- 項目を採点のたびに作ると、同じ場面でも項目が変わり、点が安定しない。
- 項目が場面と合っていない（場面に無い物が項目にある）と、正しく言えない項目が残り、点が不当に下がる。
- 何を項目にするか（主役はどれか、何の理由を問うか）には、場面の意味の判断が要る。

## Material for decision
- grill の決定（2026-11-10、ユーザーとの対話）: 作り置きのときに一度だけ作って固定する。Claude が作り、コードが裏取りする。作り置きの JSON に生成で書いた関係も残す。チェックリストを作る処理は文から場面を作る生成の PR に入れる。今の場面は、生成の実装の後に 30 場面を作り直して入れ替える。
- 調べた事実（2026-11-10）: 関係のデータからは場面と合っていることは保証できる。一方で、床・壁・背景の物も関係として並ぶので主役は決められず、理由と言い換えも作れない。
- 比べた案:

| 案 | 中身 | 良い点 | だめな点 |
| --- | --- | --- | --- |
| コードで関係から作る | 関係から中心と細部を抜き出す | 場面とは必ず合う | 理由の項目と言い換えが作れない。主役の選び方が決め打ちの規則になる |
| Claude が作り人が見る | 今の `elements` の作り方に種類を足す | 早い | 場面に無い物が項目に入っても、人が見落とせば残る |
| Claude が作りコードが裏取り（採用） | 項目ごとに、どの部品のことかを書かせ、コードで場面と照らす | 自由度は Claude、信頼性はコードと人の目で担える | 生成の出力の形が変わり、照らす処理が要る |

## Decision
- チェックリストは、場面を作るとき（作り置き・部屋での生成）に一度だけ作り、場面の JSON に保存する。採点のときには作り直さない。
- Claude が、説明文と部品・関係を書くのと同じ呼び出しで、級ごとの数（[20261110-score-content-with-checklist-f1](./20261110-score-content-with-checklist-f1.md) の表）の項目を書く。項目ごとに次を持たせる（欄の名前は生成の設計で決める）。
  - 種類（中心・理由・つながり・細部）
  - 日本語の名前（振り返りに出す）
  - 言えたとする言い方と、一部とする言い方（英語。今の `accept`・`partial` と同じ考え方）
  - どの部品のことか（部品の `key` の一覧）
- 級ごとの見本の答えも、同じ呼び出しで書く。見本は級の文法と語彙の範囲（CEFR-J）に収め、チェックリストの項目を全部含める。
- コードは、次を確かめ、合わなければその場面を使わない（作り置きでは作り直し、部屋の生成では作り置きに切り替える）。
  - 項目が指す部品が、場面に全部ある。
  - 中心の項目が指す人や動物のポーズ、関係が、項目の言い方と食い違わない（ポーズの動詞・関係の種類で照らす）。
  - 項目の数と種類が、級の形に合っている。
- 作り置きの場面は、今までどおり人が画像と一緒に確かめてから入れる。
- 作り置きの JSON には、座標（`position`）に加えて、生成で書いた関係（`place`・`facing`・`motion`）も残す。裏取りに使い、採点のときに Claude に渡す場面の情報にも入れる。
- 場面の形式（`scenenglish.scene/1`）に足す欄と、今の `elements`・`extraMax` をどう扱うかは、生成の設計で決める。

## Consequences
- 良い面: 同じ場面では毎回同じ項目で採点されるので、項目が原因の点のぶれが無くなる。
- 良い面: 場面に無い物を指す項目は、コードの確かめで落ちる。人の確かめは、主役の選び方や名前の自然さに集中できる。
- 良い面: 関係が残るので、採点の Claude が位置の関係を座標から推し量らなくてよくなる。2026-10-25 の ADR が「読み違いが多ければ切り替える」とした方式に近づく。
- トレードオフ: 生成の出力の形（Claude に書かせる JSON の形）が変わり、プロンプトと確かめの処理を書き直す。出力が増え、生成の時間と費用が少し増える（推測）。
- トレードオフ: 今の作り置きの場面にはチェックリストも関係も無いので、30 場面を作り直すまで新しい採点は使えない。
