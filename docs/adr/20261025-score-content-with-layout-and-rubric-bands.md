# 2026/10/25 内容と表現の点は、場面の配置の情報を渡し、採点基準の段階で付ける

## Status
- accepted

## Situation
- Hack Day の 2 日目。Code Freeze は 10/25 15:00。
- 採点は内容・表現・話し方の 3 項目で、重みは 50・25・25（[20261021-score-speech-with-azure-and-claude](./20261021-score-speech-with-azure-and-claude.md)）。話し方は Azure の発音評価、内容・表現と講評は Claude。本番の Claude は Sonnet 5.5 の effort `low`（PR #50、`CLAUDE_MODEL`・`CLAUDE_EFFORT`）。
- 内容は、2026-10-24 に要素ごとの加点式にしていた（[`docs/design/usecase.md`](../design/usecase.md)）。人が場面を要素に分けて配点し、Claude が要素ごとに「満点・半分・なし」を返し、バックエンドが足す。一覧に無い正しい描写は 10 点まで。
- 同じ日に、AI の場面を作り置きに変えた（[20261025-pre-generate-ai-scenes-and-pick-by-difficulty](./20261025-pre-generate-ai-scenes-and-pick-by-difficulty.md)）。場面は部品の配置の JSON で表す。

## Context
- 加点式は、作った文（要素）の一覧と照らして点を付ける。一覧に無い正しい描写は少ししか点にならず、場面に無いことを言っても点は下がらない。場面とプレイヤーの説明が合っているかを、もっと重く見たい。
- Claude に場面そのものを見せれば、一覧に頼らずに合っているかを判断できる。見せ方を決める必要があった。

## Material for decision
- grill の決定（2026-10-25）: 配置の情報を渡す、6 段階の採点基準、正確さを段階に含める、引き算の減点はしない、要素は主な見どころ、左右・前後はどの向きでも正解、表現も IELTS の考え方で段階に、段階の説明は Claude Code が下書きして野沢さんが確かめる、手作りの 6 場面も作り直す。
- 同日にいったん「場面の画像（1 方向から描いた 1 枚）を Claude に渡す」で野沢さんと合意したが、画像の読み取りに時間がかかるので取りやめた。
- 同日、grill の後に「要素は主な見どころとして渡す」を改め、要素は渡さず、場面の説明文を補足として渡すことにした。PR #55（野沢さん）の「場面ごとに説明を作り、判定に渡す」2 段の形を踏まえ、説明文は対戦中ではなく作り置きのときに書いて人が確かめる形にした。
- IELTS の Speaking の採点の観点（Lexical Resource・Grammatical Range and Accuracy）。公式の文は丸写ししない。
- 比べた案:

| 案 | 中身 | 良い点 | だめな点 |
| --- | --- | --- | --- |
| 今の要素の加点式（2026-10-24） | 人が分けた要素ごとに満点・半分・なしを返させ、バックエンドが足す | 点の根拠がはっきりする。言い回しが違っても点が下がらない | 一覧に無い正しい描写が点になりにくい。間違いを点に入れられない。要素ごとに人が配点を書く |
| 画像を渡す | 場面を 1 方向から描いた画像を Claude に渡し、採点基準で付ける | 見たままで判断できる | 画像の読み取りに時間がかかる。1 方向なので、回して見た物が写らないことがある |
| 配置の情報を渡す（採用） | 配置の JSON の部品ごとの名前・`words`・大きさ・座標・向き・動きと座標の決まりを渡し、採点基準の段階で付ける | テキストだけなので速い。場面の全部の部品が伝わる。作り置きの場面も手作りの場面も同じ形で採点できる | 位置の関係を座標から読み違えるおそれがある |

## Decision
- 内容と表現は、1 人につき Claude を 1 回呼んで採点する。プロンプトには、採点基準（段階の説明）・場面の配置の情報（metadata）・場面の説明文（補足）・文字起こしを入れる。画像は渡さない。
  - 渡すのは、配置の JSON の部品ごとの名前・`words`・大きさ・座標・向き・動きと、座標の決まり（Y が上、カメラは +Z 側）。
  - まず座標のまま渡す。場面 3〜5 個・関係を含む発話で測り、位置の関係の判定を 2 割以上読み違えたら、生成で書いた関係を配置に残す方式か、座標から関係を計算する方式に切り替える。
- 内容の点は、採点基準の段階（0・20・40・60・80・100 の 6 段階の説明。間の点も可）で 0〜100 を付ける。段階に「言ったことが場面と合っているか（正確さ）」を含め、間違いが多ければ段階が下がる。引き算の減点はしない。
- 場面の説明文（`description`）は、作り置きのときに Claude が書き、人が画像と一緒に確かめたものを補足として渡す。対戦中に説明文や採点の一覧を作り直さない。
- 要素（`elements`）は渡さない。「次に伸ばす一つ」は、Claude が metadata の中から、言えていない主な物を選んで返す。
- 左右・前後は、どの向きから見たものでも正解にする。プレイヤーは場面を回せるため。
- 表現の点も、IELTS の語彙（Lexical Resource）と文法（Grammatical Range and Accuracy）の考え方で段階を書き、0〜100 を付ける。
- 段階の説明の文は Claude Code が下書きし、野沢さんが PR で確かめる。IELTS・英検の公式の文は丸写ししない。
- 話し方（Azure）、合計の重み 50・25・25、アプリが WAV を送る API、採点の Claude のモデル（Sonnet 5.5 の `low`）は変えない。
- 手作りの 6 場面（公園・教室・駅前・雨のバス停・海辺・カフェ）も部品の配置で作り直し、同じ形で採点する。作り直すまで 6 場面は使わない。外すのは、作り置きの場面と新しい採点が本番に入るのと同時にする。それまでは今の採点で遊べるようにしておく。

## Consequences
- 良い面: 一覧に無い正しい描写も、場面と合っていれば点になる。場面に無いことや間違いは、正確さの段階で点に入る。要素ごとに人が配点を書かなくてよい。
- 良い面: 作り置きの場面と手作りの場面を、同じ形で採点できる。
- トレードオフ: 点の根拠が「どの要素を言えたか」ほどはっきりしない。同じ発話でも点がぶれるおそれがある。段階の説明の質で点の質が決まる。
- トレードオフ: Claude が座標から位置の関係を読み違えると、正しい描写が間違いにされる。読み違いを測り、多ければ渡し方を変える。
- 「次に伸ばす一つ」は、要素の配点から選べなくなるので、Claude が言えていない主な物を返す形に変える。
- 配置の JSON の `elements`・`extraMax` は新しい採点では使わない。プロトコルからは外さず、`scenenglish.scene/1` のまま残す。
- 良い面: 対戦中に Claude を呼ぶのは 1 人 1 回だけで、場面ごとの基準を覚えておく仕組みが要らない。
- 手作りの 6 場面を作り直すまでは、2 つの採点の形がコードに並ぶ。
