# 2026/11/12 遊んだ記録は端末の中だけに、1 ラウンド 1 ファイルで残す

## Status
- accepted

## Situation
- Award Day（2026-11-15）の前。アプリとバックエンドを、チェックリストの採点と英検の級の場面に切り替えるまとめ用の branch（`feat/eiken-switch`）を作っている。
- アカウントは無い。サーバーは音声を保存せず、部屋の中の採点の結果も部屋が閉じると消す。プライバシーポリシーと App Store の申告も、その前提で書いてある。
- 部屋がその場で AI で作った場面の配置（`scenenglish.scene/2`）は部屋の中にだけあり、部屋が閉じると消える。作り置きの場面の一覧も、入れ替えることがある（2026-11-11 に 30 場面へ入れ替えた）。
- 野沢さんの PR #98 が、採点の結果をサーバーに 180 日残して「きろく」の画面で見返す形を出している。

## Context
- 遊んだ本人が、前のラウンドを場面ごと見返せない。振り返り（文字起こし・内容の内訳・講評・見本の答え・自分の声）は、遊んだ直後にしか見られない。
- 本人の苦手（言えなかった項目の種類など）を出すにも、過去のラウンドの結果が要る。
- 残すものには、本人の声の録音と、話した英文が入る。どこに、どのくらい残すかは、プライバシーポリシーと申告に効く。

## Material for decision
- grill の決定（2026-11-12、ユーザーとの対話）: 保存先は端末の中だけ。1 ラウンド 1 ファイル。場面は配置の JSON をまるごと持つ。自分の結果は届いた形のまま持ち、順位とほかの人の結果は入れない。録音は記録と同じ寿命。件数や日数の上限は置かない。「すべて消す」を用意する。
- PR #98（野沢さん）: 記録に入れる欄の選び方（日時・場面・点数・文字起こし・内容の内訳・講評・場面の配置。表示名は入れない）、場面の配置も一緒に残す理由（部屋が閉じると AI の場面は取れない）、記録を振り返りの画面の形（自分 1 人の結果）に戻す持ち方を元にした。
- 比べた案:

| 案 | 中身 | 良い点 | だめな点 |
| --- | --- | --- | --- |
| サーバーに 180 日残す（#98） | 全体で 1 つの Durable Object に、端末の乱数の ID ごとに残す。アプリは開くたびに取る | アプリを入れ直しても ID が同じなら読める。開発者が集計もできる | 文字起こしと採点の結果をサーバーに長く持つので、ポリシーと申告を変える。端末の ID を知られると読まれる。録音は残せない（残すとさらに重い）。消すには窓口への連絡が要る。migration を戻せない |
| 分析用を別に保存する | 見返す用の記録とは別に、苦手の分析のための集計（項目の種類ごとの達成など）を別の形で持つ | 分析が速い。形を分析に合わせられる | 同じラウンドが 2 か所にあり、片方だけ消える・ずれることがある。分析の形はまだ決まっておらず、決める前に保存の形を固めることになる |
| 端末に 1 ラウンド 1 ファイル（採用） | アプリ用の領域に `<id>.json` と `<id>.wav` を置く。分析は、この記録を読んで計算する | サーバーとポリシーの前提（サーバーは残さない）を変えない。録音も残せる。本人が自分で消せる。通信が無くても見返せる | 機種を替える・アプリを消すと無くなる。開発者は集計できない |

## Decision
- 遊んだ記録は、端末の中だけに残す。サーバーには何も足さない。
- 1 ラウンドを 1 つの JSON（`scenenglish.record/1`）にし、アプリ用の領域（Application Support の下の `records/`）に `<id>.json` として置く。同じ `id` の自分の録音を `<id>.wav` として並べる。形の正本は [`docs/design/play-record.md`](../design/play-record.md)。
- 記録には、遊んだ日時・級・場面の配置の JSON まるごと・自分の結果（バックエンドから届いた形のまま）を入れる。順位と、ほかの人の結果は入れない。
  - 場面を ID でなく JSON まるごとで持つのは、作り置きの一覧を入れ替えた後や、部屋がその場で作った場面でも、後から同じ 3D を出すため。
- 保存するのは、自分の採点の結果が届いたとき。採点に失敗したラウンドは残さない。同じラウンドは 2 回保存しない。
- 録音は記録と同じ寿命にする。録音だけが残る状態を作らない（記録を消すときは録音も必ず消す）。
- 件数や日数の上限は置かない。本人が「すべて消す」で消せるようにする（関数は用意し、設定の画面は次の PR で作る）。
- 苦手の分析は、別に保存せず、この記録を読んで計算する。
- `records/` は端末のバックアップに入れない（実装で決めた。「端末の中だけ」「アプリを消すと消える」を文字どおりにするため。`play-record.md` の Open Questions）。

## Consequences
- 良い面: サーバーは今までどおり何も長く持たない。プライバシーポリシーは「端末の中に保存する」を足すだけで、App Store の「収集」の答えは変わらない。
- 良い面: 録音も残せるので、過去のラウンドでも自分の声を聞き直せる。通信が無くても見返せる。
- 良い面: 記録が 1 ファイルで閉じているので、作り置きの場面を入れ替えても、古い記録の 3D と見本の答えを出せる。
- トレードオフ: アプリを消す・機種を替えると、記録は無くなる。取り戻す手段は無い。
- トレードオフ: 開発者は、みんなの記録を集計できない（どの項目が言えていないかなどを、サーバーの側で見られない）。
- トレードオフ: 上限が無いので、録音（1 ラウンド約 0.6 MB まで）が端末にたまる。1000 ラウンドで約 0.6 GB。困るようになったら、上限か、録音だけ古いものから消す仕組みを別に決める。
- トレードオフ: 記録は端末にしか無いので、形の版を上げるときに古い記録を読めなくすると、本人は取り戻せない。版を上げるときは、古い版も読むか、書き直す。
- 場面の JSON を 1 件ごとに持つので、1 件が数 KB になる。
- PR #98 のサーバーに残す形は採らない。
