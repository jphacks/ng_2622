# 2026/10/25 採点の基準は、配置の JSON と部品のメタデータから作る

## Status
- superseded by [20261025-score-content-with-layout-and-rubric-bands](./20261025-score-content-with-layout-and-rubric-bands.md)（場面ごとに基準を作って覚えるのをやめ、配置の情報を座標のまま渡して採点基準の段階で付ける）

## Situation
- 場面は部品（`assets/parts`）を配置の JSON で並べて作る方向になった（[ADR](./20261024-compose-scenes-from-stored-parts.md)）。AI やエージェントが場面を作ると、人が採点の要素（`elements`）を書く余裕は無い。
- 採点は「内容×50 ＋ 表現×25 ＋ 話し方×25」で、内容と表現は Claude が要素ごとに判定している（[ADR](./20261021-score-speech-with-azure-and-claude.md)）。

## Context
- 配置の JSON に書いた要素（`description`・`elements`）に頼らず、場面そのものから採点の基準を作りたい。
- 同じ場面の全員を、同じ基準で採点したい（人ごとに基準が変わると順位が公平でなくなる）。
- 採点の待ち時間を短くしたい。

## Material for decision
- 場面の画像（斜め・真上）を Claude に見せて基準を作り、判定する案を手元で試した。公園の画像 1 枚で、基準づくりと判定を合わせて 1 人目は 23 秒（Haiku 5.5・effort high）。要素が「男の子が飛び石の上に立っている」のように 2 つのことを 1 つにまとめがちで、"I see a boy" だけで満点になった。左右・前後など見る向きで変わる言い方も残った。
- 部品のメタデータ（`label`・`words`・`pose`・`size`・`anchors`）と座標から、on・座っている・中にある・隣・近く・向き・動きを計算して文字で渡す案では、基準づくり 5.6 秒、1 人の判定 4〜5 秒（Sonnet 5.5・effort low）だった。

## Decision
- 採点の基準（場面の説明・要素・配点）は、配置の JSON の `items` と部品のメタデータから作る。画像は使わない。
  - 座標から関係を計算し、左右・前後は使わずに英語の事実の箇条書きにする（`backend/src/scoring/layout.ts`）。Claude はその事実だけから基準を書く。
  - 色は、メタデータ（`color`・`colors`）か部品の名前（`赤いボール` など）にあるときだけ使う。無い色を言われても、加点も減点もしない。
- 基準は場面ごとに 1 つだけ作り、Durable Object `SceneRubrics`（キーごとのインスタンス）に 1 日覚える。同時に作られたら、先に保存された方を全員が使う。
- 場面を選んだ時点で `POST /score/rubric` を呼べば、基準づくりを採点の待ち時間から外せる。
- 理由: 部品の ID と座標が正解そのものなので、画像を読み違える余地が無く、速い。

## Consequences
- 良い面: 人が要素を書かなくても採点できる。全員が同じ基準で採点される。画像のトークンが要らず、待ち時間は 1 人 4〜5 秒になった。
- トレードオフ: メタデータに無い見た目（服の色など）は採点に入らない。焼き込んだ同梱の場面（公園・教室など）は部品で組み立てていないので、今までどおり `scenes.json` の手書きの要素で採点する。
- 関係の計算は外接する箱を円で近似した目安で、隣・近くの境目（0.6 m・2 m）は場面によって合わないことがある。
- まだ、Claude が 1 つの要素に 2 つのこと（「男の人がベンチに向かって歩いている」など）をまとめることがある。
