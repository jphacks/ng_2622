# 2026/10/26 部屋がスタートのたびに AI で場面を作り、だめなら作り置きに切り替える

## Status
- accepted

## Situation
- Hack Day の 3 日目の夜。今回の差し替えの期限は 10/26 08:00。
- 2026-10-25 に「AI の場面は遊ぶ前に作り置き、待合では難易度だけを選ぶ」と決めた（[20261025-pre-generate-ai-scenes-and-pick-by-difficulty](./20261025-pre-generate-ai-scenes-and-pick-by-difficulty.md)）。作り置きは難易度ごとに `backend/src/scenes/pool/` に入っている。
- `POST /scenes/generate`（合言葉付き・保存しない）と、配置の JSON から座標を作る `backend/src/scenes/compose.ts` はすでにある。生成の実測は Sonnet 5.5 の low で、かんたん 3.7 秒、ふつう 4.8〜5.2 秒、むずかしい 5.9〜6.5 秒。
- wrangler の設定には、生成を止めるための変数 `SCENE_GENERATION`（いまは `off`）がある。

## Context
- 作り置きだけだと、遊べる場面は作り置いた数に限られ、同じ顔ぶれで遊ぶと同じ場面が出る。
- 今後、いろいろな場面で遊んだ学習の記録を集め、苦手な状況を見つけて出題に使いたい。そのためには、場面を数多く・幅広く作れることが土台になる。
- 2026-10-25 に作り置きにした理由のうち「ホストの一言を書いた人が有利になる」は、一言を入れずに難易度だけで作らせれば起きない。残る心配は、待ち時間・崩れた場面・本番で Claude が止まること・費用で、これは時間の上限、作り置きへの切り替え、回数の上限で抑えられる。

## Material for decision
- grill の決定（2026-10-26、ユーザーとの対話）: 目的は今後の幅（いろいろな場面と、学習の記録の土台）。生成するのは部屋（Room DO）。ホストがスタートを押したら毎回作る。10 秒で間に合わない・通信の失敗・断られた・形が違うときは、同じ難易度の作り置きに黙って切り替え、やり直さない。1 部屋 20 回まで、環境変数で止められる。ラウンドで配るのは今までどおり `sceneId` だけ。ホストが抜けたら生成を止める。
- 待ち時間の見せ方は、シミュレータで試作を比べて決めた（カード・全画面の覆い・キャラ・記号・積み木・走る人）。Apple の Human Interface Guidelines（Loading・Progress indicators）の「待つあいだもほかの操作をさせる」「やめる手段を残す」「待ちが長いなら見ていて楽しいものを出す」「ゲームなら独自のロード画面」に合わせた。
- 比べた案:

| 案 | 中身 | 良い点 | だめな点 |
| --- | --- | --- | --- |
| 作り置きだけ（2026-10-25 の決定） | 遊ぶ前に作って確かめたものを同梱 | 待たない。人が確かめた場面だけが出る | 場面の数が作り置いた分に限られる |
| アプリが生成の口を呼ぶ | 難易度を押したらアプリが `POST /scenes/generate` を呼ぶ | 作りが単純 | アプリに合言葉を持たせることになる。部屋の全員に同じ場面を配る仕組みが別に要る |
| 部屋が先回りして作る | 待合に入った時点で部屋が作っておく | スタートで待たない | 使われない生成に費用がかかる。難易度を変えると作り直しになる |
| 部屋がスタートで作る（採用） | ホストがスタートを押したら部屋が作り、全員に配る | 合言葉は Worker の中だけ。全員が同じ場面。使う分だけ作る。だめなら作り置きで遊べる | 毎ラウンド 4〜7 秒ほど待つ。人が確かめていない場面が出る |

## Decision
- ホストが `start` で難易度を送り、生成が有効（`SCENE_GENERATION` が `on`）で、その部屋の生成がまだ 20 回に満たなければ、部屋（Room DO）が場面を作る。部屋の状態は `lobby` → `generating` → `playing` と進み、`generating` は全員に配る。
- 生成の待ちは 10 秒までで、やり直さない。間に合わない・通信の失敗・断られた・形が違うときは、同じ難易度の作り置きの場面に黙って切り替えてラウンドを始める。生成が止められているとき、20 回を超えたときは、今までどおり作り置きから選ぶ。
- 生成中にホストが抜けたら（`leave`）、生成を止めて作り置きの場面でラウンドを始める。切断しただけなら止めない（戻ってくることがあるため）。
- ラウンドで配るのは今までどおり `sceneId` だけ。作った場面の配置の JSON は部屋の `ctx.storage` に置き、R2 には置かない。アプリは `GET /scenes/{sceneId}/layout?room=<部屋の番号>` で取る。採点も部屋に置いた配置の JSON を使う。部屋が消えるときに一緒に消える。
- アプリは生成の口を呼ばず、合言葉も持たない。`POST /scenes/generate` は作り置きのスクリプト用に今のまま残す。
- 待つあいだは、部屋の全員に、3D の人が走るアニメーションと「AI が場面を生成中…」を出す。文は固定にし、場面の中身のヒントになることは書かない。スタートと難易度だけを押せなくし、退出（×）は押せるまま残す。画面全体を覆って押せなくすることはしない。
- 走る人は、人が実際に走ったモーションキャプチャ（CMU Graphics Lab Motion Capture Database の 09_01、使い道に制限なし）を部品の人物に写し、連番の png に書き出して使う。ほかの待ち時間にも使える部品にする。
- やらないこと（後で issue にする）: 学習の記録を集めること、苦手に合わせた出題、作った場面を長く残すこと（R2）。

## Consequences
- 良い面: 毎ラウンド新しい場面で遊べ、同じ顔ぶれで何度遊んでも場面が尽きない。生成が止まっても作り置きで遊べるので、デモが止まらない。
- 良い面: 合言葉と Claude のキーは Worker の中だけにあり、アプリにも端末にも出ない。
- トレードオフ: 毎ラウンド、スタートから 4〜7 秒（最長 10 秒）待つ。人が確かめていない場面が出るので、崩れた場面や言いにくい場面が混ざりうる。
- トレードオフ: 1 部屋で最大 20 回、Claude を呼ぶ費用がかかる。止めるときは `SCENE_GENERATION` を `off` にする。
- 作った場面は部屋が消えると残らないので、後から同じ場面を見返せない。学習の記録や見返しに使うなら、保存先（R2 など）を別に決める。
- 部屋の状態に `generating` が増えるので、アプリはこの状態を知っている版にそろえる必要がある。
