# ScenEnglish（シーングリッシュ）

![ScenEnglish のサムネイル: 見てて楽しい英会話アプリ](docs/images/thumbnail.png)

同じ 3D の場面をみんなで同時に見て、英語で描写して競うスピーキングゲームです。AI が「何を言えたか・どう言えたか・どう話せたか」を採点し、次に伸ばす一つを教えてくれます。

## 製品概要

英語 × ゲーム × 3D：同じ場面を見て、自分の言葉で英語を話し、比べ合うスピーキングゲーム

### 背景(製品開発のきっかけ、課題等）

単語や文法を学んでも、いざ話そうとすると言葉が出てきません。私たちはその一番の理由を、話す機会そのものが足りないことだと考えました。

- 既存の英会話アプリは、決まった文をなぞる練習が中心です。自分で文を組み立てる練習になりにくく、面白くないので続きません。
- 一人で練習しても、自分の言い方が良いのか、他の人ならどう言うのかが分かりません。

同じ場面を見ても、ある人は「犬が走っている」と言い、別の人は「男の子が犬とボールで遊んでいる」と言います。私たちはこの「比べる面白さ」に注目し、友達と同じ場面を同時に描写して AI の採点で競うゲームを作りました。

|                        | 定型文を練習するアプリ | 一人で場面を描写して練習するアプリ | **ScenEnglish**                           |
| ---------------------- | ---------------------- | ---------------------------------- | ----------------------------------------- |
| 話す内容               | 決まった文をなぞる     | 自分の言葉で話す                   | **自分の言葉で話す**                      |
| 遊び方                 | 一人                   | 一人                               | **友達と同時に対戦**                      |
| 他の人の言い方から学ぶ | できない               | できない                           | **全員の描写を並べて比べる**              |
| 次に何をすればいいか   | 分かりにくい           | 点数だけのことが多い               | **「次はこれ（+N 点）」と言い換えを示す** |

### 製品説明（具体的な製品の説明）

友達と iPhone で同時に遊ぶ、英語のスピーキングゲームです。1 ラウンドは約 1 分です。

1. 部屋に集まる：ホストが部屋を作り、ほかの人は 4 桁のコードか QR コードで入ります。
2. 同時に見る：全員の iPhone に同じ 3D の場面が同じ時刻に現れます。指で回して見回せます。
3. 同時に話す：見たものを英語で描写します（最長 20 秒）。
4. 結果発表：AI の採点で順位を出し、全員の描写を並べて見比べます。
5. 振り返り：「できたこと」「次はこれ（+N 点）」「こう言い換える」「話し方のコツ」が出て、自分の声も聞き直せます。

### 特長

#### 1. 全員が同時に同じ場面を描写する、公平な対戦

順番に話すと、後の人は前の人の言い方を真似できてしまいます。ScenEnglish では全員が同時に見て同時に話すので、一人ひとりの見方と言い方をそのまま比べられます。

#### 2. 納得できる AI 採点と、次の一歩が分かる講評

| 観点（重み）  | 何を見るか                   | 採点            |
| ------------- | ---------------------------- | --------------- |
| 内容（50%）   | 場面の要素をどれだけ言えたか | Claude          |
| 表現（25%）   | 語彙・文の組み立て           | Claude          |
| 話し方（25%） | 発音・流暢さ・抑揚           | Azure AI Speech |

例文と同じかでは採点しません。場面を要素に分けて、言えた要素ごとに加点するので、言い回しが違うだけで点が下がることはありません。振り返りでは、言えば最も点が伸びる要素を「次はこれ（+N 点）」と示します。

#### 3. 描写したくなる 3D の場面

かんたん（公園・教室・駅前）とふつう（雨のバス停・海辺・カフェ）の 6 つの場面を用意しました。ふつうの場面には、車が水たまりの水をはね上げるなど、思わず描写したくなる出来事を仕込んでいます。一言のお題から、AI が部品を組み合わせて新しい場面を作ることもできます。

### 解決出来ること

- 話す量が増える：ゲームとして友達と遊ぶので、1 ラウンドごとに必ず自分の言葉で話します。
- 伸びしろが具体的に分かる：点数だけでなく、「次はこれを言えば +N 点」「この一文はこう言い換える」まで分かるので、次のラウンドですぐ試せます。
- 他の人から学べる：同じ場面への他の人の描写を並べて見られるので、自分に無かった語彙や見方に出会えます。

### 注力したこと（こだわり等）

- 「同時」と「公平さ」を特に重視しました。開始時刻を全員に配ってそろえ、通信が切れたときのつなぎ直しやホストの引き継ぎまで作り込みました。
- AI の採点を信頼できるものにしました。AI には「どの要素を言えたか」と根拠の発言だけを返させ、点の合計と「次の一手」はプログラムが計算します。
- 採点の待ち時間を約半分にしました。モデルと思考の深さ（effort）を変えて測り、点数の傾向を保ったまま Claude の時間を 6〜8 秒から 3〜4 秒にしました。

#### 特に力を入れた部分

**① 要素ごとの加点で採点し、「次に伸ばす一つ」を計算で選ぶ**

commit: [`ea8e157`](https://github.com/jphacks/ng_2622/commit/ea8e157)・[`c48d660`](https://github.com/jphacks/ng_2622/commit/c48d660)・[`f754b52`](https://github.com/jphacks/ng_2622/commit/f754b52)

LLM に点数を直接付けさせると、同じ発話でも点がぶれ、理由も分かりません。そこで Claude には要素ごとに `full` / `partial` / `none` と根拠の発言だけを構造化出力で返させ、点の合計と「次に伸ばす一つ」はバックエンドが計算します。詳しくは [`backend/src/scoring/`](backend/src/scoring/) をご覧ください。

**② 全員の「同時」をそろえる部屋の仕組み**

commit: [`773f298`](https://github.com/jphacks/ng_2622/commit/773f298)・[`8d914c8`](https://github.com/jphacks/ng_2622/commit/8d914c8)・[`038ef7f`](https://github.com/jphacks/ng_2622/commit/038ef7f)・[`0c5185c`](https://github.com/jphacks/ng_2622/commit/0c5185c)

「スタート」の合図をそのまま送ると、通信の遅れの分だけ端末ごとに開始がずれます。部屋ごとに 1 つの Durable Object が状態を持ち、1.5 秒先の開始時刻を全員に配ることで、各端末が同じ時刻に 3D の回転と録音を始めます。詳しくは [`backend/src/durable-objects/room.ts`](backend/src/durable-objects/room.ts) をご覧ください。

**③ コードだけで作る 3D ジオラマ**

commit: [`24ab870`](https://github.com/jphacks/ng_2622/commit/24ab870)・[`358c991`](https://github.com/jphacks/ng_2622/commit/358c991)

既存の 3D 素材は権利の確認が難しく、場面に合わせた調整もできません。地面・建物・人物・小物のすべてを Blender の Python で組み立て、1 本のスクリプトからアプリ用の USDZ と発表用の画像を書き出します。詳しくは [`scripts/scene/`](scripts/scene/) をご覧ください。

**④ 部品と配置のプロトコル**

commit: [`8f3d29b`](https://github.com/jphacks/ng_2622/commit/8f3d29b)・[`aa30cb7`](https://github.com/jphacks/ng_2622/commit/aa30cb7)・[`be6aec3`](https://github.com/jphacks/ng_2622/commit/be6aec3)・[`e2a3d71`](https://github.com/jphacks/ng_2622/commit/e2a3d71)

場面をまるごと AI に作らせると、待ち時間が長く品質も読めません。そこで部品 63 個を先に作り置き、学習者が言いそうな文 300 本で調べて効果の大きい部品から作りました。詳しくは [`docs/design/scene-protocol.md`](docs/design/scene-protocol.md) をご覧ください。
